Direct camera visibility for existing roof batches — 2026-11-02
===============================================================

Prototype scope and ordering contract
-------------------------------------
This tests the first stage of direct building-batch culling: existing static,
opaque roof batches only. The accepted town shader and 128 m batching policy
remain enabled. Walls, facade alternatives, glass, doors and both shadow passes
retain their original source-level queries. No larger parent batches are added.

A camera index contains each non-roof source plus one entry per roof batch.
Its batch bounds are unions of the original full transformed source bounds,
including geometry extending beyond the nominal tile. It does not run the full
source query first and then deduplicate its results. A fully contained batch
emits its minimum source ID directly. Partial frustum/range batches resolve
member bounds, retaining the minimum selected ID and exact selected-source count.
A single-member batch needs no second membership check after the coarse query.
This preserves the old batch's draw position relative to coplanar surfaces.

The existing source BVH already skips per-member bounds tests for fully contained
nodes; this prototype additionally avoids emitting and processing their individual
roof IDs. Representatives pass through the existing detail/material/sort pipeline.
Roof sources have no detail alternative, so exact source statistics can be restored
by adding the omitted selected roofs after detail filtering. Source topology,
geometry, collision and transforms remain authoritative and unchanged.

The new RoofVisibility module owns its cached roof bounds/membership and camera
index. Its query is const; temporal plane hints are caller-owned and separate
from the original camera and light histories. Non-roof bounds are duplicated in
the additional camera BVH while the original source index remains for shadows
and the existing batching-disabled path. This memory/startup cost is part of the
prototype; it is not a scene streaming or asset-generation change.

Correctness checks
------------------
The new CPU regression compares representative sets and exact source counts with
the original source query across camera positions, scope FOVs, horizontal ranges,
culling on/off and repeated history reuse. It includes reflected/sheared geometry
crossing a tile boundary and a batch envelope intersecting the view while neither
member is visible. A contained 400-roof batch must emit one representative with
399 extra sources, one coarse node and zero individual member-bound tests.

The existing GPU source-order test checks offscreen/lower-ID members, scope
changes and coplanar ownership. Roof rendering checks preserved counts with
batching toggles, reflected geometry and sun shadows; building/shadow tests cover
the surrounding facade, door and alpha state. The full CMake rebuild succeeds;
all 24 graphics/weapon-overlay tests plus roof batching, roof visibility and model
visibility CPU tests pass. The existing unused debugMessage warning remains.

Timing protocol
---------------
The source and direct query paths alternate in one Renderer/GPU context. Both
indexes stay allocated in both modes, avoiding construction/allocation differences
inside the measured blocks. The control is compiled against matching current
headers/libraries; compiler dependencies and a linker map exclude a second
renderer.cpp object. Root sources/shaders/executables are frozen before timing.

Primary: four processes, three standard views (daytime town, flashlight town,
old forest 100 m), eight blocks/view, 60 warmup and 512 measured render+glFlush
calls/block. A final GPU retirement wait is included in elapsed wall time.
No per-frame CPU clocks/GPU timestamp queries run in primary rendering. Base
order is source/direct/direct/source/direct/source/source/direct; process orders
are base/inverse/inverse/base. Four adjacent differences per process/view are
reduced to their median, then the four process medians are reduced to a median.
Positive source-minus-direct means saving. Independent flat levels use block
medians per mode/process and medians across processes.

The predeclared clear-gain rule requires >=1% paired saving, all four process
medians positive and >=12/16 faster pairs. Regression is symmetric; other results
are mixed. This practical rule is not a significance or equivalence test.

Diagnostics: two additional base/inverse processes, 128 measured frames/block,
asynchronous whole/opaque/glass GPU timestamps with up to four frames in flight.
CPU clocks separate query, detail filtering, material classification, sorting
and submission. Counters include logical visible sources, selected entries,
selected roof batches, coarse item tests and partial-batch member tests.
Phase instrumentation does not determine primary throughput classification;
elapsed GPU intervals include submission/stalls and do not isolate shader work.

Both controls require AC offline and balanced profile, monitored every 0.5 s.
All inputs/cameras, 1280x720 resolution, reversed float32 depth, 1024-square sun
map, normal filtering/ranges and deterministic 60 Hz animation input match the
preceding town experiments. There is no AI/audio/player/dynamic physics or window
presentation workload. Clocks, temperature and background work remain unlocked.

Results and retained scope
--------------------------
Retain the roof-only camera path, with a limited performance claim: this battery
control supports a daytime-town improvement, not a universal win. The later AC
follow-up below is mixed. Walls/detail alternatives and larger parent batches
remain separate experiments. The existing town shader remains enabled.
