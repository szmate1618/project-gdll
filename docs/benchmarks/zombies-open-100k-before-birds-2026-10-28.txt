Open 100k: pre-bird historical build versus current — 2026-10-28
==============================================================

Result
------
The pre-bird build also takes about 21 ms CPU render time under today's
conditions. The comparison does not reproduce a large slowdown introduced
after birds were added. Small differences remain within observed run drift.
Every measured frame submits all 100,000 actors; all eight captures and
metadata files are byte-identical.

The historical revision was extracted into a new ignored source directory and
compiled in a separate build directory. No checkout, reset, source restoration,
or reuse of project object files was involved. Existing dependencies were reused
as source inputs, with FetchContent fully disconnected. Dependency pins and
Box3D patches are identical. Only benchmark_zombie_crowd was built, so no map,
audio, weapon or doodad asset generators ran. The current target was rebuilt too.

Both targets use /usr/bin/c++, Release, -O3 -DNDEBUG -std=c++17,
-Wall -Wextra -Wpedantic, GLFW_INCLUDE_NONE and GL_GLEXT_PROTOTYPES.
Historical configuration disables optional multiplayer targets; the benchmark's
compile flags and definitions match the current target. Historical headers and
libraries come from its own build, avoiding cross-revision class-layout mixing.

The benchmark harness, frame_profile.hpp/.cpp, and all 16 shared shader files
are byte-identical between the two sources. Each binary ran with its own source
directory as cwd, so literal "shaders" resolves to the matching shader directory.
Both read the same absolute assets/zombies/models path and write separate outputs.

Read-only GPU telemetry records activity, clock states and temperature every

the required three idle samples. Idle pre-samples do not prove absence of other
system activity during measurements, and clock samples are not synchronized
to draws. No claim of matched clocks, temperatures or power limits is made.

Background-process checks
-------------------------
Actual host process lists were inspected outside the sandbox PID namespace.
The first check found only the intentional comparison runner between runs,
with GPU activity at 0%. A second check of /proc executable paths found only
the historical benchmark actively launched by that runner; no older benchmark,
viewer or repository diagnostic binaries were found. After completion, the
host audit found no remaining benchmark, build or comparison-runner processes.
No processes were killed. These checks do not inventory every possible GPU client.

Interpretation
--------------
The standard benchmark does not instantiate bird flocks or BirdRenderer. Bird
creation, update and draw callbacks live in the viewer's main.cpp, which this
harness does not link. Core Renderer has no bird ownership/dispatch, and the
first bird commit changed no shared basic/shadow shader. Added bird static-library
dependencies do not themselves run bird code or construct bird GPU resources.

This compares complete revisions, including intervening zombie visibility and
profiling changes. It is not an isolated measurement of bird gameplay cost.
The older quiet October 20 measurements around 18 ms CPU are not reproduced by
either binary here. The gap from those older results remains unexplained by
this experiment; the pre-bird revision already measures around 21 ms today.
