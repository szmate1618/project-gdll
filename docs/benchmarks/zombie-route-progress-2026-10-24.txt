Scenario route progress and remaining movement experiments — 2026-10-24
======================================================================

Decision
--------
Keep bounded float-corner recovery, forward reconnection to the existing path,
its exact-key memo, ordinary-frame fallback for stationary distant plans, and a
whole-frame coverage guard when several movement slices are combined. Retain
simple skips for unchanged gameplay spatial updates and unused stationary
facing arithmetic. Do not retain the cheaper ground guard, persistent facing
cache, or longer movement segments. No threading, new gameplay flags, runtime
path search, teleport, mesh-tolerance relaxation or ground-query removal.

Base: 77a8b92. Work branch: experiment/zombie-route-progress-20261024.
All four requested steps were investigated. This round primarily fixes route
progress; aggregate CPU and paused-actor costs are reported separately below.

Stall diagnosis and retained behavior
------------------------------------
A rejected 100 ms proposal could produce zero velocity while a frame-sized
proposal remained valid. Caching that stationary segment caused repeated waits;
zero-length segments now take the ordinary guarded frame step.

Double portal corners can round to float positions on the wrong side of their
outgoing boundary. A bounded 5x5 neighborhood of representable coordinates is
searched around the existing corner. The complete incoming and outgoing
connections must be covered, and actual movement remains speed-limited. If
avoidance/interpolation loses sight of a stored segment, reconnect locally
forward along that same segment. Near corners, only corner recovery applies;
returning to the incoming line there could oscillate between adjacent floats.
No path search or waypoint rewrite is involved.

The reconnection result depends only on the immutable mesh, current stored path,
segment, exact position, speed and dt. Keep a separate per-ID cold memo, allocated
at population setup, to avoid repeating failed calculations while stationary.
Cold plan replacement, reset, release and population replacement invalidate it.
A regression reproduced an initially missing cold-replacement invalidation.
All this state is owned and updated by the serialized simulation thread.

Combining covered legs in one frame does not prove the complete frame chord
covered. Before appending another leg/fallback, validate the original-frame
start to the final endpoint; otherwise publish only the accepted partial step.

Rejected ground guard
---------------------
Revisited the cheaper endpoint-height envelope after corner fixes. It changes
how ground descent is protected: a height envelope alone can lower a body into
road geometry. The user accepts road overlap but not lost route progress.
Adding the ordinary solver's clear-contact condition when lowering ground fixed
one prolonged road-overlap stall. Combined with an intermediate reconnection
version, it had 26 stalled actors and zero non-ground body contacts, but retained
some ground overlap and did not demonstrate a dependable CPU advantage.

In an earlier balanced A/B round, baseline 1.846758 ms, corner version 1.927772,
memo version 1.753158. The descent guard measured 1.780187 ms in one invocation
and 3.110178 in another, so its pooled timing is not a trustworthy saving.
Do not compare these intermediate implementations as if they were the final
forward-reconnection version. Keep conservative swept/contact checks and current
position ground sampling with the existing candidate cache.

Root transforms and spatial updates
-----------------------------------
A persistent 20-byte facing cache per actor was tried. Properly rebuilt v2
controls produced byte-identical 60-second root/transforms, animation clocks,
progress and sampled trajectories. ABBA invocation means (ms):
  control 1.748111; cache 1.760855; cache 1.824175; control 1.853307.
The pooled difference is only 0.45%, smaller than host/run variation. Reject
that state and its invalidation complexity.

Keep a stateless skip of unused facing trigonometry while stationary, and call
gameplay spatial/bounds updates only when root/render transforms change or
removal/ragdoll/invalid-asset handling requires it. Initial/population/rig edits
retain explicit rebuilds. Moving/turning actors retain the existing calculations.

A separate paused-looking fixture, perception disabled before behaviors are
created, measures the relevant case. Six samples/mode at 1,600 actors:
control ~0.08025 ms, skip ~0.03656 ms; spatial calls 1,600 ->0 per update.
At 10,000: ~0.4990 ->0.2378 ms. This is a paused-actor fixture, not a whole-game
FPS or moving-horde gain. The earlier paused.log fixture was invalid because
it disabled perception after creating behaviors; use paused-v2.log only.

Limits and next evidence
------------------------
The remaining 23 low-progress actors are not claimed fixed. They may include
physical road/ballast, tree/crowd obstruction and other route/ground interactions;
this run does not establish each one's cause. A useful follow-up is categorize
these particular IDs before more approximations. Longer segments and a cheaper
ground guard do not currently justify replacing the retained policy. Threading
remains outside this experiment. No GPU rendering algorithm changed.
