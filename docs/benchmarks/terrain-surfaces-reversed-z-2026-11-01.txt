Terrain-conforming surfaces and reversed camera depth
Recorded 2026-11-01; experimental branch experiment/terrain-surfaces-reversed-z.
Baseline source: 44494d1c188ccd3d4077740d644befd0d98a294c.

Implementation and data
Roads, paths and railway beds are intersected with the published terrain triangle
planes and placed 0.001 m above them. Coordinates are quantized to the GLB float32
lattice before height sampling. Collapsed clipping slivers are removed before
export; existing topology/solid validation remains enabled. The new optional
terrain_conforming mesh marker delegates collision to terrain. Unmarked legacy
surfaces retain collision. Camera color uses FP32 reversed depth with zero-to-one
clip control; CPU visibility, shadows and menus retain conventional projection.

The published map was regenerated with --offline --surfaces-only, keeping all
original town/terrain/fence binary bytes. Navigation and default vegetation were
regenerated normally; all 33,541 individual tree instance records are identical.
Pole/HEV placements and guardrails were regenerated from offline caches. Their
physical geometry is identical. The 1,000 authored car placements were retained
and their map binding revalidated only after checking unchanged terrain, town
buffers and these obstacle layers. Historical placement provenance was retained.
No fingerprint checks were disabled. Navmesh geometry/adjacency bytes are exactly
identical to the original; only the source-fingerprint part of its header differs.

100,000-zombie rendering control (1280x720)
All 100,000 actors and ten character variants render every measured frame:
10 draws, 6,000,000 camera triangles, normal LOD3 policy, no distance shortcut.
Idle simulation and deterministic 60 Hz animation/preparation remain included.

Separate-process trials initially showed higher GPU elapsed values for FP32
formats: aggregate GPU means 6.422 / 6.840 / 6.740 ms (24 / FP32 / reversed).
Because CPU load and scheduling can affect this integrated GPU, a further
matched control rotates all three modes in one process for six rounds, with
32 warmup and 64 measured frames per mode/round. Untimed fences finish warmup.
Completed-block time includes simulation, preparation, rendering, benchmark
bookkeeping, query scheduling and final GPU draining, with no per-frame completion
wait or VSync.

All eight processes completed with instrumentation/control pose equality and
no runtime path searches. Each final population had 1,600 actors, zero blocking

was zero at reported precision; overlay variants reached 4.34 mm (optimized)
or 2.90 mm (full). Cross-variant pose equality is not required because support
heights change. Both independent quality checks pass.

The 1,000 batch finds 999 routes and reports one blocked endpoint; all successful
endpoint/segment/inflated-OBB checks pass and arenas are fully reclaimed.
Pure pathfinding is not expected to improve: the navigation graph is unchanged.

Reproduction
Use docs/BENCHMARKS.md for the tracked harness interfaces. Exact run scripts,
CSV data, metadata, captures, quality checks and analysis.json are retained at:
build/benchmarks/terrain-surfaces-20261101/.
run_benchmarks.py produced the map and process-separated crowd comparisons;
run_cpu_benchmarks.py resumed only the collision/navigation stages after
placement revalidation. crowd-alternating/ is the focused within-process control.
Original map/shaders/binaries were saved before implementation. The earlier
map-baseline/ diagnostic overlapped background work and is excluded; the fresh
map-original-measured/ run is retained separately. No production completion
waits, power changes, network downloads, or asset fingerprint bypasses were used.
