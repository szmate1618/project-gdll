Scenario traveler navigation, contact regions and distant movement — 2026-10-24
===============================================================================

Decision
--------
Retain navigation fast paths and conservative physical contact-region proofs.
Retain lower-rate steering combined with a conservative swept collision guard
for distant scenario travelers. Reject the two standalone movement prototypes.
Keep all changes on experiment/zombie-distant-travel-20261024, based on 2024927
(experiment/zombie-contact-efficiency-20261024). No threading was introduced.

Final headless controls: 1.821564 -> 1.407276 ms/update, 22.75% lower than the
pre-experiment baseline. Against the same new binary with distant movement
turned off: 1.776478 -> 1.407276 ms, 20.78% lower. That full-mode control varied
substantially between its two invocations; standalone experiments below provide
independent evidence for the exact navigation/contact improvements.

Fixed-step viewer simulation: 2.890813 -> 2.466461 ms, a 14.68% reduction in the
mean of four per-run medians. This compares the new binary's full and optimized
movement modes, not the older baseline. Hardware variation remains material.
No rendering changes were made; GPU differences do not establish less GPU work.

Retained behavior
-----------------
1. Navigation retains its generation-checked path handle instead of finding it
   by actor ID each update, reuses the current polygon before global location,
   and computes final-goal distance only when the final leg needs it. Planning
   still happens once at load. No runtime path searches were added.
2. Physical candidate patches cache conservative maximum triangle heights,
   clipped to the patch's X/Z rectangle. When those bounds prove every possible
   static contact is harmless under existing walking rules, omit the static
   triangle contact tests. Float-coordinate error, body radius and wall padding
   participate in that proof. Trunks, doors and props keep their separate checks;
   uncertain/overflowing patches use the old solver. The complete contacts API
   is unchanged. This differs from the rejected single-ground-support sharing
   experiment: one cold patch proof can eliminate many subsequent contact tests.
3. Scenario travelers beyond 200 horizontal meters from every player can refresh
   steering/short movement segments at 10 Hz. Return to full movement within
   160 m of any player; no players permits distant travel. Stable ID staggering
   spreads initial refreshes. Application dt >50 ms uses full movement.
4. The distant segment uses conservative swept horizontal wall segments and
   trunk circles. Wall inflation covers the third triangle vertex and building
   clearance. Potential door sweeps, live props, unusual geometry and candidate
   overflow force full movement. Ground must be terrain with the original slope
   limit. Intermediate ground remains sampled at the current position; sharp
   crests/dips outside the endpoint envelope force a full step. Crowd sweeps and
   navmesh validation run on every accepted current step. Rejection starts a
   250 ms full-movement cooldown.

Authoritative feet, crowd membership, root transforms and locomotion clocks
continue to advance every frame. Rendering, shooting, perception and replication
use those same current feet; no future endpoint is published as the actor pose.
Perception still hands scenario actors permanently to original behavior. Original
behavior never requests navmesh paths and always uses its original movement.
World replacement, changed feet, looking, mode changes and takeover discard any
pending segment. '--full-scenario-movement' disables distant approximations for
comparison; the exact navigation and contact-region changes remain enabled.

Ground heights were not made stale or replaced by the rejected arithmetic cache.
The lookahead/fallback policy actually increases ground query count in this case.
These segment refreshes are movement decisions along the existing path, not
new path searches. Profiling's traveler_plans field counts segment refreshes.

Measurement protocol and clock correction
-----------------------------------------
Release builds, output/godollo.glb, matching .navmesh/assets, seeded scenario 42:
1,600 actors (1,000 random + 600 crossing), 1,160,022 collision triangles and
155,825 trunks. Stationary player X=-526.465, Z=296.095. Sequential measurements;
no builds or other experiments run concurrently with timings. No power/CPU/GPU
settings changed. All 38 timed invocations began/ended in balanced mode; all 460
two-second power samples reported AC online. This does not fix hardware clocks.

Headless: CPU 0, dt=1/60. Each invocation reloads the population six times,
alternating three detailed and three control runs; each has 60 warmup +300
measured steps. Each listed invocation contributes 900 controls and 900 detailed
samples. Controls disable fine-query timers and determine performance decisions.
Detailed stage times are exclusive but heavily perturbed by tiny-query clocks.
No migrated timer samples were dropped. Loading, startup planning, rendering,
audio, networking and physics advancement are excluded. Props/doors are queried
at live but unchanged poses in this fixture.

Viewer: hardware OpenGL, 1280x720, same fixed street camera, hidden window,
480 frames; discard frame IDs 1..60. No audio, time 12.3, day length 0,
--animation-time 0. Final controlled viewer runs additionally use --fixed-step,
which advances SimulationClock and simulation dt by 1/60 s per rendered frame.
Both modes therefore advance exactly eight simulated seconds over 480 frames.

Important correction: --animation-time only freezes the render animation input.
It does NOT freeze or fix SimulationClock. Earlier viewer @final and @visible
cases used wall-clock dt, so different runtimes advanced different simulation
amounts and changed timed AI work per frame. Preserve those as wall-clock
observations; do not combine them with fixed-step results or treat them as
controlled movement-work comparisons. Earlier reports' frozen animation wording
likewise does not imply fixed simulation. AGENTS.md and BENCHMARKS.md now warn
agents to match and record timestep policy. The existing fresh-source-mtime/CMake
restore warning remains beside it. No timestamp-preserving restores were used.

Verification and limits
-----------------------
- Built viewer, server, affected tests, benchmark, validator and collision corpus.
  All 25 affected suites pass (3.80 s), including shared collision/steps/doors,
  navigation/scenario/travel, perception/takeover, crowd, movement, root updates,
  shooting, spatial index, frame profiling and server integration.
- Differential walking-contact tests cover terrain/road/platform classifications,
  slope/seams, large coordinates, several radii/heights, walls/trunks/ceilings and
  live boxes. Only originally nonblocking supports may disappear. A small-radius
  capsule with large wall padding exposed an unsafe proof bound; the final bound
  includes maximum wall reach, and the regression is retained.
- Existing 48,000 contact +96,000 ground-query corpus is byte-identical to baseline.
- ASan+UBSan instrumented the changed collision, movement and travel objects and
  ran both movement/travel suites successfully; not every app dependency was
  instrumented.
- Independent untimed 600-frame/1,600-actor real-map validation: 960,000 actor-step
  samples each for full and selected. Both have 0 physical blocking penetrations,
  0 navmesh escapes, 0 speed violations and 0 crowd overlaps. Selected has three
  padded-skin overlap samples; full has five. Zero-skin contacts are checked
  separately, with the original walking support exemptions.
- Float-coordinate quantization matters: at ~3 km one ULP is ~0.25 mm. The first
  validator's origin-sized speed tolerance falsely flagged tiny rounded steps.
  The corrected independent bound includes both endpoints' coordinate precision;
  production movement did not need a speed change.
- Maximum vertical offset from a separate ground query over 10 s is 0.449892 m
  in BOTH full and selected modes. Existing rounded-foot/ledge support can differ
  from a vertical ground ray. Final six-second max is 0.042594 m full and 0.071865 m
  selected. Do not claim exact vertical-ray matching over the real-map trajectory;
  flat/sloped terrain tests do check current rendered height directly.
- Distant steering paths can diverge near obstacles (outlier above). Moving or
  newly spawned props can enter a previously accepted segment before its next
  refresh (up to 100 ms). Potential door hinge sweeps already force full checks.
  Nearby actors retain full movement. The real-map validation did not advance
  dynamic physics, so it is not proof for every moving-prop/terrain/map case.
