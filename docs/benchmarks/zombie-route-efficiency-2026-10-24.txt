Retained changes and limits
Steering: every navigation state owns TrunkCandidates, at most 32 static IDs
in a query AABB padded by 0.5 m on each side. Reuse only when the entire current
query is covered and the immutable collision-world identity matches. Filter
stored trunks by current AABB/height and exact circular range; retain BVH
order, bounded output and overflow behavior. Overflowing caches use the full
BVH. Tree geometry is immutable for this world's lifetime. This is candidate
reuse, not stale steering velocity or skipped avoidance. Cache sizeof on this
build is 176 bytes/actor, about 275 KiB for 1,600 actors. Dense tree neighborhoods
may still fall back; large crowds pay the additional cache memory.

Crowd: retain the 1 m fine grid and add population counts for 8x8 m sectors.
If the entire radius-expanded swept query lies inside the indexed actor's
sector and that sector contains only itself, no other body can be a candidate.
Return the same unobstructed endpoint without fine-cell hash lookups. Otherwise
run the existing sweep/slide solver, ID ties and shared neighbor budget.
Sector counts change immediately on commit/removal, so later actors observe
earlier movement as before. Neighboring sectors are never assumed empty.
Fine-cell relocation increments the destination count before erasing its old
membership; this preserves the referenced sector node. Copying rebinds body
references to the copied map; moves retain stable unordered-map nodes.
The coarse map is bounded by occupied sectors; body metadata and node counts
add memory. This benefits sparse travel and is not an avoidance shortcut in
packed crowds. The final real-map fixture skips about 1,075 of 1,597 sweeps per
update (67.3%); it still checks all actual neighbors.

Waypoints: reject coordinates clearly farther than twice the comparison radius
before hypot. Near the 0.15 m arrival and 10 micrometer reached boundaries,
keep the exact original hypot comparisons. Target normalization, waypoint
coverage checks and numerical corner handling remain. This avoids most distant
radius calculations without a squared-distance rounding change.

Profiling: all scopes remain opt-in/exclusive. Parent lines are self-time;
children belong to their own lines. CPU whole-update control runs disable
fine clocks. Inactive Timer objects now initialize only the profile pointer;
all other fields are initialized inside the enabled branch before use. Root
pose timing covers heading/matrix and locomotion-clock updates, not skeleton
sampling or animation palettes. Render notifications only queue dirty IDs.

What next / limits
The measured root-pose cost is about 0.22 ms with fine timing; render dirty
notifications about 0.05 and activation/dispatch about 0.01. Those are small
ceilings compared with ground/contact work. No skeleton evaluation occurs in
this pose stage. Skipping unchanged spatial updates may help stationary idle
or attacking actors, but nearly every traveler moves in this fixture.

The best next exact experiment is sharing a proven supporting surface between
ground selection and contact handling, or certifying that a walkable support
face cannot block the current capsule. Preserve seams, edges, step ceilings,
overlapping surfaces and live props; do not substitute a stale height. Ground
and triangle contact stages remain material after steering/crowd savings.

Route/navigation/body control also deserves a more targeted split before
changing it: consolidate duplicated result bookkeeping only where unchanged
positions/coverage/heading inputs can be proved. Storing a path handle rather
than hashing the ID every follow is another small candidate, with generation
and release/reset semantics preserved. Pose matrix reuse needs exact input
invalidation; raw yaw/normalization caching could change legacy rounding.

Cache size/patch tuning and 4/8/16 m crowd sectors can trade memory, occupancy
hit rate and refresh cost. Retain dense overflow/boundary fallbacks, and measure
sparse versus packed layouts. Approximate collision, slower update cadence,
skeleton/render optimization and worker threads remain separate future work.
Threading is still last; no large future speedup is promised from a small stage.
